# Leveled List Viewer Instructions

* NEVER implement a fallback solution to read nif files from anywhere else than the `meshes` folder in the skyrim installation
* Always ignore character casing when looking up files on the file system
* How to determine which body slots are used by some outfit: Make a list of slots defined by all ARMO records. Ignore both the slots defined in the ARMA records and the NIF files
* When to add standard meshes for feet, hans & body: ONLY if the respective slots are not used by ANY ARMO record of the outfit currently under display
* Body skin (NIFs and textures for slot 32 / 33 / 37) must follow the in-game resolution chain: NPC's WNAM → race's WNAM. No vanilla fallback when an NPC is selected. If neither NPC nor race resolves a slot's NIF (or textures), the slot is left unloaded / untextured and the failure is signaled both in the status bar and in the log.
* **The NPC's FaceGen NIF is the complete head.** It overrides every head definition on race level or in the NPC record (RACE / NPC_ head parts, HDPT NIFs). `LoadHeadMesh()` loads only the FaceGen NIF; HDPT NIFs are not loaded on top of it. Skin NIFs (body / hands / feet) may carry the race's original head-part geometry (shapes named after HDPT editor ids); `LoadNifFromPath()` ignores those shapes so they don't render as a second face.
* **Skin retexture is gated by the Skin Tint shader flag**, matching game behavior. Only `NiTriShape` blocks whose `BSLightingShaderProperty.bslspShaderType == BSLSP_SKINTINT` (nifly: `IsSkinTinted()`) receive the NPC's NAM1 TXST and QNAM tint. Every other shape — including 3BA-style secondary anatomy shapes (vagina/anus) that share partition 32 with the body — keeps its NIF-embedded `BSShaderTextureSet` untouched. This rule applies uniformly to body-chain shapes (body/hands/feet NIFs) and to outfit shapes; slot routing for the TXST array is by source NIF slot for the body chain and by dismember partition for outfit shapes. Vertex-count or texture-name heuristics for picking a "reference body" are NOT used and must not be re-introduced.
* Race body / hair visibility (slots 31 hair, 32 body, 33 hands, 37 feet) at runtime is driven by what is **currently shown**, not by what the outfit declares. Implemented in `ApplyRaceBodyPartVisibility()` and re-run after every outfit-shape checkbox toggle so deselecting a covering outfit shape re-reveals the underlying race body part (and re-selecting it hides it again).
* **Plugin loading is eager and single-pass**: `LoadAllActivePlugins()` runs once from `LoadESP()` after the main-ESP master chain is read, and pulls every active plugin from `Plugins.txt` (in load order) into the dynamic-master cache via `EnsureDynamicMaster()`. There is no lazy-resolve / on-demand load path — every RACE / ARMO / ARMA / TXST / OTFT / LVLI / NPC_ override the user's load order produces is in cache by the time the first consumer fires. NPC override records whose EDID is renamed by the override plugin (a CK organisation convention) are remapped to their canonical editor id via `npcEditorIdByMasterFormId` at scan time.
* **Head morphs follow the BodySlide preset**: heads are loaded as static FaceGen meshes but the previewer now applies the active preset's slider morphs to each head shape too, via `ApplyPresetToHead()`. Morphs are looked up in the `.tri` file alongside the head NIF and matched by NIF shape name + preset slider name; morphs the head `.tri` doesn't carry are silently skipped. This closes the neck seam that would otherwise appear when the body's neck verts have been morphed but the head's haven't.
* **Outfit-piece NIF loading is lazy along the gate path.** `LoadOutfitMeshes()` builds `useAnyGroups_` first, then calls `EnsurePiecesLoadedForActivePath()` to load only the pieces whose `useAnyPath` is currently active. With every group's default `activeIndex = 0` that's the "all-zero" path; other variants are loaded on demand when the user activates them via `SwitchUseAnyVariant()` or `ActivateVariantChain()`, which call `EnsurePiecesLoadedForActivePath()` before `ApplyUseAnyVisibility()`. The race-tier filter (`renderPieceIdx_`) is computed once per outfit and reused by the lazy-loader. Loaded piece indices live in `loadedOutfitPieces_` and are cleared together with `useAnyGroups_` / `shapeUseAnyPath_` whenever the outfit changes. Without this, NPCs whose DOFT chains into mod-injected leveled lists (bandits, dungeon-filler "Adventurer" NPCs) would expand to thousands of pieces and stall the load by reading every variant's NIF up-front.

## View modes

The left-hand pane is a `wxNotebook` with two tabs:

* **Outfits** — leveled-list / outfit browser as before (search + level filters + outfit list).
* **NPCs** — NPC browser. Selecting a row loads the NPC's head + race body + skin textures and, if available, automatically renders the NPC's **default outfit** (NPC_ `DOFT` → `OTFT`).

Keys in the 3D view (it takes the keyboard focus when the mouse moves over it): `T` textures, `F` wireframe (also **View → Wireframe**), `U` untextured meshes, `B` body; the movement keys are described under Animation below.

The currently selected NPC (`currentHeadEditorId`) is preserved across tab switches; switching tabs never clears the head or body. The `Head` text field at the top of the panel remains the shared selector and is updated whenever an NPC is picked in either tab.

## Default outfit (DOFT) resolution

* `NPCRecord.defaultOutfitFormId` is parsed from the `DOFT` subrecord and remapped from the source plugin's master space into the loaded ESP's `espMasters` space (last-writer-wins across overrides).
* `LeveledListData::ResolveNpcDefaultOutfit(npc)` looks up the `OTFT` in `otftCache` and builds an `OutfitEntry` on demand, caching it in `npcOutfitCache` keyed by editor id.
* `OTFT` `INAM` entries pointing at `LVLI` are expanded via `ResolveLVLIGrouped` and treated as **Use Any** groups. The previewer's default `UseAnyGroup::activeIndex = 0` naturally selects the **first valid variant**, matching the requirement.
* NPCs whose DOFT points at an OTFT or LVLI defined in a plugin **not** in the loaded ESP's master chain currently resolve to nullptr; the previewer logs the unresolved case and leaves the NPC standing in race body + head only.

## Animation and SMP physics

The **Animation** checkbox (config key `AnimEnabled`) plays an animation of the actor's character, by default its standing idle, the clip the race menu shows. The field next to it shows the playing animation; its `...` button opens the character's animations with a search field: a click plays an animation right away (and turns Animation on), OK keeps it (config key `AnimClip`, the name as the character file lists it), Cancel goes back to the animation and Animation state from before; **Pause** holds the animation at its current time while physics keeps running. The **SMP Physics Preview** checkbox (config key `SmpEnabled`) runs FSMP on the actor. Both can be on at the same time; while either is on, the meshes are posed, simulated and skinned every frame (at most ~60 per second). A frame only starts once the event loop is idle, so clicks and repaints always come first and the controls respond at once; setting the actor up (loading its files, equipping its models after a change, switching the animation) shows the busy cursor. Implemented in `src/components/ActorAnimation.*` on top of the Havok reader in `src/files/HkxFile.*` and FSMP in `src/fsmp/` (see `src/components/agents.md`).

### The actor

* The actor is an FSMP scene (`fsmp::Actor`): the race skeleton NIF (RACE `ANAM` for the NPC's sex) is the actor's 3D. Every model the previewer loads is registered with `ActorAnimation::RegisterModel()` right after its shapes were added to the GL surface, and the actor wears it the way the engine equips it:
  * Race skin NIFs (body, hands, feet) and outfit pieces are attached as armor: FSMP's armor attach event (FSMP merges the model's nodes into the skeleton, renaming them with its `hdtSSEPhysics_AutoRename_Armor_…` prefix), the model's skin bound to the skeleton's nodes by bone name, attach event again (FSMP builds the physics system).
  * The NPC's FaceGen NIF is attached through FSMP's head skinning events (`SkinAllHeadGeometryEvent` / `SkinSingleHeadGeometryEvent`); FSMP binds the head's bones and reads its physics the way it does for a FaceGen head in game. For NPCs with FaceGen data, FSMP takes the physics of all head parts (hair included) from the FaceGen NIF: its `HDT Skinned Mesh Physics Object` string extra data or `defaultBBPs.xml` matching its shape names, one physics file per face (FSMP's README). Head part NIFs (HDPT) are not read, and the head geometries carry no face model data (FMD) pointing at them.
  * Order: armors in load order, then the head.
* Which models are worn follows what the game equips: an outfit piece while its Use Any variants are active (`IsUseAnyPathActive`), a race skin model unless shown outfit shapes cover all of its slots (`ApplyRaceBodyPartVisibility`), the FaceGen head always. Shapes hidden for display only (helper / collision shapes, unchecked shapes) stay on the worn model, as in game, so FSMP uses them.
* Each model is attached as a clone, like the engine clones cached models. The clone carries the meshes' current rest pose, preset morphs included: when the preset or the weight changes (`RestPoseChanged()`), when the worn set changes or when a checkbox is toggled, the actor is set up again from scratch.
* The actor's records as FSMP reads them: NPC form id and name, race skeleton paths, the Havok rig with its reference pose (FSMP builds physics systems in it) and the inventory: every worn outfit piece's ARMO with its biped slots, marked as worn (FSMP's `disableSMPHairWhenWigEquipped` looks for worn hair / long hair slot armor there). Race skin models are not inventory items. Without a selected NPC, the vanilla female actor files are used and there is no head.

### Animation

* **Clip resolution follows the game's chain**, no hard-coded clip paths: RACE `MODL` after the `NAM3` marker (behavior project for the NPC's sex, e.g. `Actors\Character\DefaultFemale.hkx`) → `hkbProjectStringData.characterFilenames[0]` → `hkbCharacterStringData`: `rigName` (e.g. `skeleton_female.hkx`) and `animationNames`, the animations offered by the `...` button. The saved choice is matched by its path, then by its file name (male and female characters keep their clips in different folders); otherwise the entry whose file name is `MT_Idle.hkx` plays. All paths in these files are relative to the behavior project's folder. Files are read loose first, then from archives (`LeveledListData::ReadGameFile`).
* Without a selected NPC the outfit is shown on the vanilla female body, so the vanilla female actor files (`skeleton_female.nif`, `defaultfemale.hkx`) are used. This is the only default; with an NPC selected, a race without `ANAM` is an error (log + status bar, no motion), a race without `MODL` or a broken clip chain is an error that only disables the idle.
* The chosen clip loops on its own. The behavior graph is not evaluated: no random idle variations (sigh, shoulder roll, …), no transitions, no blending.
* **Movement keys** (3D view focused, Animation on): while held, the game's default controls play the animations the game uses for them, unarmed and running (the game's default), looked up by file name in the character's animations: `W`/`A`/`S`/`D` `MT_Run<direction>` (`Forward`, `Backward`, `Left`, `Right`, diagonals such as `ForwardLeft`; opposite keys cancel out), `Ctrl` (sneak) `SneakMTIdle`, with a direction `SneakRun_<direction>`, `Space` `MT_Jump` once, then `MT_JumpFall` looping; jump takes precedence over the other keys. Releasing the keys (or the 3D view losing the focus) returns to the chosen animation where it left off. These animations play while Pause is on, too. A file name the character doesn't list is an error (log).
* Supported data: 64-bit `hk_2010.2.0-r1` packfiles (Skyrim SE) with `hkaSplineCompressedAnimation`. Other Havok versions, 32-bit (LE) files, additive clips and the `THREECOMP24` / `STRAIGHT16` rotation encodings are rejected with an error.
* **Pose**: each frame the clip is sampled; rig bones without a track get the rig's reference pose. Rig bones are bound to the actor's nodes by name, case-insensitively like the engine; rig bones without a node are not displayed (logged). Nodes the clip doesn't drive keep their NIF transform. World transforms are then updated for the whole actor, like the engine's node update.

### SMP physics

* FSMP runs as in game: its configuration comes from the loose `Data/SKSE/Plugins/hdtSkinnedMeshConfigs/configs.xml` (FSMP's defaults apply without it), physics files from the `HDT Skinned Mesh Physics Object` string extra data of a model's root or from `defaultBBPs.xml`, every frame is one frame event and one frame sync event with the time since the last frame. Errors in physics files (unknown bones, bad elements) are reported and handled by FSMP itself; its log lines go to the log with an `FSMP:` prefix (FSMP's trace and debug lines only in verbose logs).
* The engine around FSMP is emulated by `src/fsmp/FsmpScene.*`: data files are read relative to the Data folder, loose files first, then archives (a path starting with `Data\` is read relative to the Data folder too, as the previewer did before; how the engine treats that prefix is not verified), there is no world geometry (nothing blocks the line of sight), no weather (no wind), and the camera is at the actor (it is never culled).
* Without physics, nothing simulates: the worn models' bones follow their parents.

### Skinning

* **Skinning** happens on the CPU for every visible skinned shape of a worn model: `Σ w · boneWorld · skinToBone · v`, using the shape's own skin data and the world transforms of the bones its attached clone is bound to (after FSMP wrote its bones). At most four influences per vertex (the strongest are kept, the rest are dropped with a warning), no weight renormalization. Unweighted vertices collapse to the origin, as in game. Unskinned shapes stay static.
* **Rest-pose invariant**: posed vertices exist in a mesh only between `ActorAnimation::Update()` and `RestoreRestPose()` inside one actor frame (`ActorFrame()`; the GPU keeps the posed copy). All other code — preset morphs, morph-base capture — always reads and writes the rest pose. New mesh-loading paths must register their models with `actorAnim_.RegisterModel()` after `GLSurface::AddMeshFromNif()`.

## "Load all NPCs" button

By default only vanilla NPCs and overrides reachable from the loaded ESP's master chain are listed. The **Load all NPCs** button scans every non-vanilla plugin in the data directory for *native* `NPC_` records (top-byte == self) and appends them via `LeveledListData::LoadAllPluginNativeNPCs()`. After the scan the autocomplete map and the NPCs list are rebuilt.
